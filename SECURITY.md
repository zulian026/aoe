## 2. Reporting a Vulnerability

If you discover a potential security vulnerability in AOE, please **do not** open a public issue.

Instead, please report it privately via **GitHub Security Advisories**:

1. Navigate to the repository's **Security** tab on GitHub.
2. Click **Report a vulnerability** to open a private advisory draft.
3. Include detailed reproduction steps, environment details, and affected packages.

We will acknowledge receipt within 48 hours and work with you to analyze, patch, and coordinate public disclosure.

## 3. Security Architecture & Guarantees

AOE is built with explicit security constraints designed for handling untrusted outputs from AI agents:

### 3.1 No Automatic Command Execution

AOE is strictly a presentation and telemetry engine. It **never** executes shell commands, scripts, or binaries derived from agent outputs, event payloads, or user configurations.

### 3.2 No Agent Configuration Tampering

AOE does not alter, inject, or tamper with external agent configuration files, environment settings, or global agent hooks. External agent configurations are treated as strictly read-only.

### 3.3 Defense-in-Depth Terminal Sanitization

Text rendered to the terminal undergoes multi-layered sanitization:

- **OSC Sequences**: Operating System Command escapes (e.g. window title manipulation `\x1b]0;...`, clipboard setting `\x1b]52;...`) are filtered out.
- **Dangerous CSI Sequences**: Cursor repositioning, screen clearing, and alternate buffer escapes are stripped from untrusted text before display.
- **Trojan Source Protection**: Unicode bidirectional override and isolate characters (`U+202A`–`U+202E`, `U+2066`–`U+2069`) are stripped to prevent visual source spoofing.
- **Control Characters**: Null bytes and unprintable ASCII control characters (excluding standard tabs and newlines) are removed.

### 3.4 Secret and Credential Masking

AOE includes heuristic masking patterns for sensitive tokens:

- Bearer tokens (JWTs, OAuth)
- OpenAI & Anthropic API keys (`sk-...`)
- Google AI API keys (`AIza...`)
- AWS Access Key IDs (`AKIA...`)
- GitHub Personal Access Tokens (`ghp_...`, `github_pat_...`, `gho_...`)
- Slack tokens (`xox...`)
- Standard key-value secret assignments (`password=...`, `secret: ...`, `api_key=...`)
- Private key blocks (`-----BEGIN ... PRIVATE KEY-----`)

### 3.5 Private Thought Suppression

Agent internal reasoning tags (`<thought>`, `<scratchpad>`, `<antThinking>`, `<internal_reasoning>`) are removed prior to rendering to protect developer privacy.

### 3.6 Memory and Streaming Bounds

- **Maximum Record Size**: Individual JSONL lines are bounded (default 5MB) to protect against buffer memory bloat.
- **Stream Ceilings**: Stdin stream reading enforces a 50MB safety ceiling preventing denial-of-service from runaway processes.

---

## 4. Known Security Limitations

- **Heuristic Secret Masking**: Regular expression secret masking is a defense-in-depth heuristic. It cannot guarantee detection of high-entropy secrets formatted with unconventional names or proprietary formats. Developers remain responsible for avoiding secret emission in agent tool outputs.
- **ANSI Styling in Untrusted Strings**: Legitimate styling escapes generated by AOE components are preserved, but arbitrary color codes in untrusted input may affect text appearance if not stripped via `--mode static` or non-TTY pipes.
